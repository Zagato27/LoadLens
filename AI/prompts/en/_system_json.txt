Strictly JSON with the schema: {verdict, confidence, findings[], recommended_actions[]}. The verdict field is a code: pass | risk | fail | no_data. Every findings item must contain: id, summary, severity (critical|high|medium|low), component, start_time, end_time, peak_time, evidence_summary, evidence_items[]. Every evidence_items item must be an object {metric, observed_value, threshold, note}. id must be a short ASCII identifier like f1, f2. Every recommended_actions item must be an object: {summary, details, priority (critical|high|medium|low), affected_components[], for_finding_ids[]}. The details field must contain a detailed description of the action: what exactly to change, why, and how to tell that the problem is fixed. The for_finding_ids field must refer to one or more ids from findings. If component is not stated, extract it from evidence_summary using the labels application|service|job|pod|instance, otherwise 'unknown'. If severity is not stated, use 'low'. The peak_performance field is allowed ONLY for the lt_framework domain or the final overall analysis (if the context contains designated_peak_performance). Do not add peak_performance for other domains.
