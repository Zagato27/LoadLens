ЗАДАЧА: Комплексный отчет по метрикам базы данных в ходе нагрузочного тестирования

ИСХОДНЫЕ ДАННЫЕ:
- Объем запросов в DB (total requests)
- 95-й перцентиль времени запросов

РЕКОМЕНДУЕМЫЕ ОРИЕНТИРЫ:
- P95 latency: < 100 мс (предупреждение: 100–200 мс; критично: > 200 мс)

ТРЕБОВАНИЯ К АНАЛИЗУ:
1) Проанализировать указанные метрики по всем подам/сервисам, доступным в данных.
2) Указать минимум/среднее/максимум и характерные окна времени.
3) Найти корреляции: рост объема запросов vs рост P95 времени выполнения.
4) Сопоставить фактические значения с рекомендуемыми ориентирами и выделить отклонения.

ТРЕБОВАНИЯ К НАСЫЩЕННОСТИ И ФОРМАТУ (ВСЕ ТЕКСТОВЫЕ ПОЛЯ — НА РУССКОМ):
- Минимум 5 пунктов в findings и 5 в recommended_actions (если данных достаточно).
- Для каждого findings укажите фиксированные поля: id, summary, severity (critical/high/medium/low), component, start_time, end_time, peak_time, evidence_summary, evidence_items[].
- Каждый элемент evidence_items должен быть объектом {metric, observed_value, threshold, note}.
- id у findings должен быть коротким ASCII-идентификатором вроде f1, f2.
- Каждый элемент recommended_actions должен быть объектом {summary, details, priority, affected_components[], for_finding_ids[]}, где for_finding_ids ссылается на один или несколько id из findings.
- Поле details обязательно: опишите конкретные изменения, ожидаемый эффект и способ проверки после внедрения.
- Отвечайте СТРОГО в JSON: {verdict, verdict_rationale, confidence, findings[], recommended_actions[], affected_components[]}.
- Поле verdict ДОЛЖНО принимать только одно из: "Успешно" | "Есть риски" | "Провал" | "Недостаточно данных".
- Поле verdict_rationale ДОЛЖНО кратко объяснять вердикт: сначала 1-2 предложения с итогом, затем 2-4 ключевых фактора списком.
- Если данных недостаточно — верните verdict="Недостаточно данных" и объясните причину в findings.
