# План: вторая волна улучшений интерфейса

Цель: после рестайлинга (сайдбар, Inter, токены, акцент `#6c5ce7`, 2026-10-15) сделать интерфейс
не только современным, но и быстрее объясняющим результат теста: маркеры и пороги на графиках отчёта,
KPI и тренды на дашборде, быстрая навигация, умные формы, единые состояния загрузки и мобильная вёрстка.
Стек не меняется: Flask + Jinja + ванильный JS + Chart.js 4.4.1, CSP без `unsafe-eval`, вендорные ассеты.

## Статус реализации (2026-10-15)

| `/lt_windows` с правом `_read()` | `_read(E)` | Эндпоинт ходит в источники метрик, как живые метрики прогона |
| «Обычно около N мин» по задачам того же вида | `/jobs?status=done&limit=20`, фильтр по виду на клиенте, нужно не меньше трёх | У `/jobs` нет фильтра по виду; задачи не хранят режим ИИ и публикации |
| Плотность — `body[data-density]` | `:root[data-density]` | Скрипт до первой отрисовки работает раньше, чем появляется `body` |
| Тема по умолчанию | Без сохранённого выбора — тёмная, как раньше; «Как в системе» выбирается явно | Не менять вид у существующих пользователей |
| Сравнение — `syncHover` | Только масштаб | На странице сравнения открыт один график |
| — | Демо-прогон хранит окно SLA, выбранную ступень и явные `query_label`/`series` у проверок | Иначе демо-отчёт не показывал зону SLA и пороги шли через запасной разбор |

Оставшиеся ограничения: подписи маркеров идут по часам отчёта, а деления оси — по часам браузера (совпадают для
UTC+3); подсветка ступени работает от мыши, не с клавиатуры; кэш `/lt_windows` у каждого процесса свой;
`@media print` глобальный, поэтому печать любой страницы идёт без меню и в светлой теме.

## 0. Принципы и общая база

Принципы:

- Ось X графиков остаётся категорийной (`labels` = ISO-строки минутных корзин). Адаптер дат и `type: 'time'`
  не вводим: метки времени переводятся в индекс подписи бинарным поиском по `Date.parse`.
- Плагин `chartjs-plugin-annotation` не вендорим: маркеры и пороги рисуем своими плагинами
  (`afterDatasetsDraw`, по образцу `zonesPlugin` и `stepNumbersPlugin` из `static/js/forecast_report.js:93-126`).
- Всё, что появляется на графике в вебе, появляется и в PNG для Confluence
  (`loadlens_app/confluence_export.py: render_series_png`), иначе отчёт в Confluence будет беднее.
- Детерминированные данные важнее текста ИИ: `parsed.peak_performance.max_time` и `drop_time` пишет LLM
  (`AI/scoring.py:535-560`), маркеры строятся только из таблицы ступеней и окна SLA.
- Новые эндпоинты получают запись в `loadlens_app/auth/policy.py` и тесты в `tests/test_smoke_api.py`.

Общая база (этап 0, до остальных):

## 1. Страница отчёта

Файлы: `templates/reports.html`, `static/js/reports.js`, `loadlens_app/confluence_export.py`, `static/css/app.css`.

### 1.1 Маркеры событий и зоны

Источник данных — итоговая строка `/llm_reports` (`domain == 'final'`), всё уже на клиенте:

| Маркер | Откуда | Вид |
|---|---|---|
| Последняя стабильная ступень | `sla_details.stable_window.start/end` (`AI/sla_evaluator.py:43-71`) | полупрозрачная зона цветом `--accent-soft`, подпись «SLA: ступень N» |
| Границы ступеней | `sla_details.load_step_table.steps[].start_iso` (`AI/context_pack.py:615-669`) | тонкие штрихи по оси X без подписи |
| Точка деградации | ступень после выбранной (`stable_window.degraded_level`, `degraded_checks`); для стресса `parsed.saturation.rps_drop_iso` и `saturation_window` (`AI/saturation.py:117-177`) | вертикальная пунктирная линия `--status-fail`, подпись «деградация HH:MM» |
| Всплеск (spike) | `parsed.spike_analysis` (окна всплеска) | зона `--status-warn` с альфой |
| Окно удержания (soak) | `parsed.stability_under_load` (hold window) | зона `--accent-soft` |

Реализация:

- `reports.js`: функция `reportMarkers(finalRow)` рядом с `renderLoadSteps` (1661-1697) собирает список
  `{t: ms, kind: 'line'|'band', to?: ms, label, tone}`; `reportsDrawOne` (1921-1989) передаёт его в
  `plugins: [LL.charts.markers, LL.charts.thresholds]` через `options.plugins.llMarkers`.
- `LL.charts.markers`: `afterDatasetsDraw`, индекс подписи ищется по `chart.data.labels` (отсортированы),
  `x = scales.x.getPixelForValue(index)`; подписи рисуются `ctx.fillText` вверху, не перекрывая друг друга
  (сдвиг на строку при пересечении).
- Шрифт подписей берётся из `Chart.defaults.font.family`; цвета из `LL.ui.chartColors()`.
- Таблица «Ступени теста» (`renderLoadStepTableHtml`, 1605-1641): наведение на строку подсвечивает ступень на всех
  графиках домена (`chart.options.plugins.llMarkers.highlight = index; chart.draw()`).

### 1.2 Пороги SLA

- `renderSlaChecklist` (1317-1354) уже парсит `message` проверки через `hintFromCheck` (1387-1393): оттуда берутся
  `query_label` и `series`. Функция `slaThresholds(finalRow)` отдаёт `{query_label, series?, value, label, tone}` для
  `p95_latency`, `p99_latency`, `error_rate`, `target_rps`, `cpu_usage`, `memory_usage`.
- В `reportsDrawOne` порог рисуется только если `ql` графика совпадает с `query_label` проверки; серия не фильтруется.
- `LL.charts.thresholds`: горизонтальная пунктирная линия `--status-fail` (`--accent` для `target_rps`) с подписью
  «p95 ≤ 300 мс» справа; если порог выше максимума данных, ось Y растягивается (`scales.y.suggestedMax`).
- SLA-таблица: колонка «Факт» получает мини-бар (`div.sla-bar` с шириной `min(actual/threshold, 1.5) * 100%`,
  цвет по статусу); для `target_rps` бар растёт в сторону «больше лучше».

### 1.3 Синхронный ховер и масштаб

- `LL.charts.syncHover(charts)`: на `mousemove` одного холста вычисляется индекс ближайшей подписи, на остальных
  вызывается `setActiveElements` и `tooltip.setActiveElements` с тем же индексом, затем `update('none')`; на `mouseleave`
  всё сбрасывается. Группа — графики одной вкладки домена (`renderDomainPane`, 2235-2248).
- `LL.charts.zoom(charts)`: перетаскивание по холсту рисует полупрозрачный прямоугольник (`afterDraw`), на отпускание
  ставит `scales.x.min/max` (индексы) всем графикам группы; кнопка «Сбросить масштаб» появляется в панели вкладки.
  Колесо мыши не используем, чтобы не ломать прокрутку страницы.
- Tooltip общий: `interaction.mode = 'index'`, `intersect = false`, строки отсортированы по значению, не больше 12 серий
  с «ещё N».

### 1.4 Легенда под графиком

- `renderDomainPane`: `.cmp-chart-wrap` становится колонкой; холст на всю ширину, высота 260 px
  (`maintainAspectRatio: false`), легенда — `div.legend-chips` под ним: чипы `[цвет] имя · среднее`, клик выключает
  серию, кнопки «Все», «Ни одной», «PNG» справа. При более чем 12 сериях чипы сворачиваются в прокручиваемый блок
  высотой 120 px с поиском по имени.
- `syncLegends`, `scheduleLegendSync`, `attachPanelObservers` (2083-2151, 2283-2293) удаляются.
- `downloadChartWithLegend` (1991-2041) переходит на тот же список видимых серий; маркеры и пороги попадают в PNG
  автоматически, потому что рисуются на холсте.
- CSS: `.cmp-legend-panel` остаётся для страницы сравнения до этапа 5, где сравнение переводится на тот же вид.

### 1.5 Hero с числами

- `renderHero` (1753-1808): над `renderHeroMeta` добавляется ряд `.kpi-row` из трёх плиток: `max_rps`

### 1.6 Липкие вкладки и печать

## 2. Дашборд

Файлы: `templates/dashboard.html`, `static/js/dashboard.js`, `loadlens_app/blueprints/dashboard.py:306-432`.

### 2.1 API `/dashboard_data`

- `services[].history: [{run_name, run_id, created_at, verdict, max_rps, test_type}]` до 5 записей: SQL уже выбирает
  эти поля для всех строк, `_group_service_rows` (283-303) выбрасывает всё кроме вердикта; в SELECT добавляется
  `COALESCE(run_id, '')`. `recent_verdicts` остаётся для совместимости.
- Дедупликация по `run_name` через `ROW_NUMBER() OVER (PARTITION BY run_name ORDER BY created_at DESC)` в CTE
  для `services` и `recent_runs` (сейчас прогон с несколькими итоговыми строками показывается дважды).
- `kpi: {runs_7d, runs_30d, risky_share_30d, last: {max_rps, test_type}, previous: {max_rps, run_name}}`,
  где `previous` — предыдущий прогон того же сервиса и типа теста (условия как в `AI/db_store.find_previous_run`, 493-575).
- `verdict_weeks: [{week_start, counts: {...}}]` за 8 недель (`date_trunc('week', created_at)`) вместо подсчёта только
  по последнему срезу.
- `last_run.sla: {passed, total}` из `sla_details.checks` итоговой строки.

### 2.2 Интерфейс

- Карточка «Последний запуск» становится hero: пилюля вердикта, «SLA 2/3», три KPI-плитки (max RPS со стрелкой
  и процентом к `previous`, окно теста, тип), обычная кнопка «Открыть отчёт» вместо `btn-tile`.
- Пончик заменяется столбчатой диаграммой «вердикты по неделям» (stacked bar, цвета `--status-*`), которая осмысленна
  и при одном прогоне.
- Таблица «По сервисам»: вместо точек — инлайн-SVG спарклайн по `history[].max_rps` (без Chart.js) плюс дельта
  к предыдущему прогону; точки вердиктов остаются как цвет точек спарклайна.
- Верхний ряд: плитки `runs_7d`, `risky_share_30d`, активные задачи (`/jobs`), последнее обновление.

## 4. Формы

### 4.1 Сервис как поисковый комбобокс

- `templates/index.html:77-80` и `templates/launch.html`: `<select id="service">` заменяется на `ui.combobox`
  с `fetchOptions` по локально отфильтрованному ответу `/services` (`dashboard.py:252-280`); значение дублируется
  в скрытый `input[name=service]`, чтобы `createReport` (`new.js:210-262`) и `readForm` (`launch.js:351-372`) не менялись.
- Недавние сервисы (`LL.prefs.recentServices`, до 5) показываются первыми с пометкой «недавно».
- При одном сервисе комбобокс заполняется сразу, как сейчас делает `loadServices` (`new.js:92`).

### 4.2 Подсказка окна теста

- Новый эндпоинт `GET /lt_windows?service=&hours=6` (policy `_read`), реализация в
  `loadlens_app/load_tests/live.py` рядом с `report_filter` (186-204): берётся строка роли `lt.rps_total`
  (`_block_rows`, 48-80), запрос за последние `hours` часов с шагом `choose_step` (36-39), ряд режется на
  непрерывные отрезки с RPS > 0 (пауза больше 3 шагов разрывает отрезок), возвращаются последние три:
  `{start, end, duration_sec, rps_peak}`. Ограничение `hours ≤ 24`, число точек в пределах `limits.py`.
- Второй источник — завершённые прогоны сервиса из `GET /load_tests/runs` (`started_at`/`finished_at`).
- UI на «Новом отчёте»: под полями периода ряд чипов «Найденные прогоны: 15:57–16:57 (60 мин, пик 249 RPS)»;
  клик подставляет `start`/`end` и вызывает `validateRange` (`new.js:111-139`). Загружается после выбора сервиса,
  ошибки источника показываются тихо (`field-hint warn`).

### 4.3 Прогресс и страница запуска

  завершённых задач того же вида из `GET /jobs?status=done&limit=10` (нужен статус `done` в `JOB_STATUSES` фильтра).

## 5. Полировка и мобильная вёрстка

- Тема: переключатель в подвале сайдбара становится меню «Вид» (`details.menu`) с пунктами «Как в системе»,
  «Светлая», «Тёмная» и «Плотность: обычная / компактная». Скрипт до первой отрисовки (`base.html:9-17` и копии в
  `login.html`, `recovery.html`, `storage_unavailable.html`) при значении `system` берёт `matchMedia('(prefers-color-scheme: light)')`;
  `ui.theme` слушает `change` этого медиазапроса.
- `@media (prefers-reduced-motion: reduce)`: без шиммера скелетонов, без анимации drawer и тостов.
- Плотность: `body[data-density="compact"]` уменьшает отступы ячеек до 6 px, высоту полей и кнопок до 32 px,
  `--radius-sm` до 6 px.
- Скелетоны и пустые состояния через `LL.ui.skeletonRows`/`emptyRow` в `forecasting.js`, `compare.js`, `users.js`,
  `account.js`, `settings.js` (сервисы); пустые состояния сравнения и прогнозирования получают иконку из спрайта и
  одну кнопку действия.
- Страница сравнения переводится на легенду под графиком и общую палитру (как 1.4).
- Мобильные таблицы: класс `.data-table.responsive`; JS проставляет `td[data-label]` из заголовков; при
  `max-width: 720px` строки становятся карточками (`display: grid`, подпись из `data-label`). Применяется к архиву,
  дашборду и прогнозированию.
- Скриншоты в `docs/screenshots` пересняты под новый интерфейс (README ссылается на старые).

## 8. Риски и решения

| Риск | Решение |
|---|---|
| Маркеры по индексу подписи неточны, если корзины неравномерны | Корзины `/run_series` минутные и непрерывные (`compare.py:306-359`); при пропусках ищется ближайшая подпись, расхождение не больше половины шага |
| `message` проверки SLA меняет формат, и порог теряет график | `hintFromCheck` уже зависит от формата; в `AI/sla_evaluator._make_check` добавляются явные поля `query_label` и `series`, JS читает их с запасным разбором `message` |
| Синхронный ховер на 8 графиках по 15 серий тормозит | `update('none')` без анимации, троттлинг `requestAnimationFrame`, серии сверх 12 скрыты по умолчанию с кнопкой «Показать все» |
| Подсказка окна теста ходит в источник метрик с каждой формы | Запрос только после выбора сервиса, кэш на 60 с на сервере, лимит `hours ≤ 24` |
| Палитра команд даёт доступ к страницам не по роли | Список страниц строится из тех же `nav_items`, которые Jinja уже отфильтровал по `role_rank`; сервер всё равно отвечает 403 |
| Тема `system` мигает при загрузке | Тот же синхронный скрипт до первой отрисовки, `matchMedia` вычисляется там же |
| Печать тёмного отчёта расходует тонер и теряет контраст | В `@media print` принудительно светлые токены и перерисовка графиков перед печатью |
| Два источника правды для маркеров (JS и Python) | Общий контракт фиксируется тестом на демо-строке; при расхождении правится обе стороны в одном коммите |
